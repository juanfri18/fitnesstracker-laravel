01 — Introducción

¿Qué es SinergyFit y por qué existe?

El problema
Las apps existentes son limitadas

Apps como Strava son o muy complejas o demasiado simples. Los entrenamientos de fuerza se reducen a un cronómetro y estimación de calorías. Sin registro de ejercicios, series ni pesos.

La motivación
Convertir una rutina en un hábito

Quedarse estancado en el gimnasio es común. Con un registro real puedes ver cómo empezaste hace tres meses y cómo estás ahora. Eso es lo que crea adherencia.

¿Qué permite SinergyFit?

  • Registrar cada ejercicio de fuerza: grupo muscular, series, repeticiones y peso
  • Registrar sesiones de carrera y caminata
  • Ver la evolución del volumen levantado a lo largo del tiempo
  • Establecer objetivos y seguir su progreso
  • Ver rachas y desbloquear logros para motivarse
Tipos de actividad
🏋️ Fuerza 🏃 Carrera 🚶 Caminata

El todo es mayor que la suma de sus partes.

05 — Dificultades

Problemas durante el desarrollo

Problema 01
Empezar con PHP puro (sin framework)
  • Cada página mezclaba SQL, validaciones, HTML y CSS en un mismo archivo
  • El login, las sesiones y la protección contra SQL injection había que programarlos desde cero
  • Añadir funcionalidades implicaba copiar y pegar código entre páginas
  • El código creció hasta ser imposible de mantener
Resultado: fue más eficiente reescribir la aplicación entera que intentar seguir sobre esa base.
Problema 02
La migración a Laravel

Migrar no es copiar el código. Hay que reaprender cómo se organiza todo:

  • La estructura de la BD pasa a migraciones versionadas con Git
  • Las consultas SQL se reescriben como código Eloquent
  • Las páginas se reorganizan en controladores + vistas Blade
  • Login, validación y sesiones los gestiona Laravel de forma segura por defecto
Resultado: base sólida, código limpio y mantenible. La inversión mereció la pena.
05 — Dificultades · Docker

De 18 segundos por clic a < 200ms

Al desplegar en Docker en Windows, cada página tardaba 10-18 segundos. No era un problema, eran cinco problemas apilados:

CausaTiempo perdido
Volume mount Windows (WSL2)7 – 9 s
Sin OPcache activado2 – 3 s
Modo debug activo (APP_DEBUG=true)1 – 2 s
Sin caches de Laravel generados0.5 s
Assets cargados desde CDN externo1 – 3 s
Total10 – 18 segundos
Causa principal
Volume mount + WSL2

Laravel carga más de 300 archivos PHP del framework en cada petición. Con el volume mount activo, cada lectura cruzaba el puente de traducción WSL2 (Windows → Linux), sumando 7-9 segundos antes de ejecutar una sola línea de código.

La solución
Código dentro del contenedor

Se eliminó el volume mount. El código vive en el filesystem nativo Linux del contenedor (copiado en el docker build). Además: OPcache activado, modo producción, caches de Laravel generados al arrancar y todos los assets descargados dentro de la imagen.

Después

06 — Preguntas frecuentes

FAQ

¿Por qué Laravel y no otro framework?
Es el framework PHP más usado, con la mayor comunidad y documentación. Ofrece el equilibrio perfecto entre potencia y curva de aprendizaje para un proyecto académico de este nivel.
¿Por qué PHP y no Node.js o Python?
PHP sigue siendo el lenguaje servidor más extendido en la web (WordPress, Wikipedia...). Laravel lo eleva al nivel de frameworks modernos. Además era el lenguaje con el que más experiencia tenía.
¿Se pueden añadir más tipos de entrenamiento?
Sí. Solo hay que añadir el nuevo tipo en la validación del controlador y en la fórmula de calorías. La estructura de la base de datos no requiere ningún cambio.
¿Funciona en móvil?
Sí. La interfaz está construida sobre Bootstrap 5, que es responsive por diseño y se adapta automáticamente a cualquier tamaño de pantalla.
¿La aplicación es segura?
Sí, a varios niveles: contraseñas con bcrypt, protección automática contra SQL injection con Eloquent, escape de datos en Blade contra XSS, tokens CSRF en todos los formularios y límite de 5 intentos de login por minuto contra ataques de fuerza bruta.
¿Cómo se despliega la aplicación?
Con un solo comando: docker-compose up --build. Docker levanta automáticamente los tres contenedores: servidor web (PHP + Apache), base de datos MySQL y phpMyAdmin.
¿Qué cubren los tests automáticos?
La aplicación tiene 8 tests con PHPUnit que verifican el cálculo de calorías por tipo, la validación de objetivos y el cálculo de estadísticas con y sin datos. Detectan regresiones automáticamente si se modifica el código.
